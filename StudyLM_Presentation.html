07 / How RAG Works

What is RAG?

RAG = Retrieval-Augmented Generation — the secret sauce behind StudyLM!

🔍
1. Retrieve
Search your document for the most relevant paragraphs using smart vector search
→
📋
2. Augment
Add those relevant paragraphs as "context" into the AI prompt
→
✨
3. Generate
AI creates answers, notes, or MCQs based ONLY on your actual document
✨ Result: AI never makes up facts — everything comes from YOUR study material!
08 / Data Pipeline

How Documents Are Processed

When you upload a file, here's what happens behind the scenes:

1
📤 Upload File
Save PDF/TXT/MD to server disk
▼
2
📄 Extract Text
PyMuPDF reads PDFs page by page
▼
3
✂️ Split Into Chunks
Break text into 1000-char pieces (200 overlap)
▼
4
🧠 Create Embeddings
Google Gemini converts text → number vectors
▼
5
💎 Store in ChromaDB
Save vectors for fast similarity search
▼
✓
✅ Ready to Study!
Document is indexed and all features are available

11 / Database

How Data Is Stored

Two databases working together — one for metadata, one for AI search

🗄️
SQLite Database
Purpose: Stores document info

Table: documents

Columns:
• id, filename, original_name
• file_path, file_type, file_size
• num_pages, num_chunks
• collection_name (links to ChromaDB)
• status (processing → ready)
• created_at, updated_at
💎
ChromaDB (Vector Database)
Purpose: Smart text search

How: Each document gets its own collection

Stores:
• Text chunks (original paragraphs)
• Embeddings (number vectors)
• Metadata (chunk index)

Enables: "Find the most relevant paragraphs for this question"

17 / Security

Security Considerations

Area How We Handle It Status
🔑 API Keys Stored in .env file, never in code or git ✅ Secure
🛡️ SQL Injection SQLAlchemy ORM prevents injection attacks ✅ Protected
📊 Quiz Cheating Answers stored server-side, never sent to browser ✅ Anti-cheat
